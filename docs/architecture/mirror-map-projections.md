# Mirror map — projection drain and consumption rules (code side)

Maintained with the code it indexes. Owner module for the registry-walk drain that the command layer,
the emitter fallback and the two Shopify seed commands use: `backend/projections/runtime.py` (PR #155).
The Celery task (`projections/tasks.py`), the `run_projections` operator command and the tenant replay
command keep their own walks under Rule 20's per-file pins. This map lists where each rule is stated or
enforced, so that a change to a rule touches every mirror in one commit.

## How to use it

Before changing any rule below, open its owner and every place listed under "also stated / enforced";
change them together or say in the PR why one deliberately differs. Ratchets are the tests that fail
when a mirror drifts; they are listed so a change knows which test it will trip.

Conventions:

- A path that starts with `backend/`, `docs/`, `scripts/` or `.github/`, or names a root file (`README.md`,
  the root `.env.example`), is relative to the repository root; every other path is relative to `backend/`.
- "Rule N" is the numbered section header in `tests/test_architecture_rules.py` (for example "Rule 6b" and
  "Rule 20"); a test belongs to the header that precedes it. The unnumbered "Meta" section is named as such.
- The characterisation suite `tests/test_projection_drain_characterisation.py` names its tests by drain
  shape (`test_v1_*`, `test_v2_*`, `test_v3_*`, `test_v5b_*`, `test_v6_*`) plus one shape-independent test,
  `test_registry_enumeration_is_live_and_insertion_ordered`; it is cited by test name.

## Deferred decisions that will edit these rows (all under the one ADR that NEXT_TASKS A175 produces; A175 is P1 backlog)

- Drain structure — drain only at the outermost command boundary, or restrict the in-command drain to the
  read-model projections a command needs. Changes the owner semantics of the registry-walk row, the drain-order
  row (whole-registry walk), the `command_drain` description in the gate row and the nested-drain notes of the
  in-flight row.
- F-K — a per-company projection lock across connections (worker processes and the web workers'
  synchronous drains). Adds a rule to the in-flight row; until then the runbook prescribes worker
  `--concurrency 1` (§G1d, proven at §G1e).
- Routing the Celery task, `run_projections` and tenant `replay_projections` through `drain_company`
  (`projections/runtime.py` docstring: "until an ADR under A175 decides otherwise"). Changes the
  registry-walk, Rule 20, drain-order, runtime-context and handler-failure rows (the other walks' context
  and swallow behaviour) and the Rule 20 pins. A175's "six drain copies" wording predates PR #155; the
  command-layer copies are already one.
